# yfere decision contracts

Status: implementation-grade planning contract; runtime code does not yet exist.

## Contract rules

All external and catalog inputs cross a Zod runtime boundary. Types are closed where IDs and variants are closed; unknown values are explicit (`unknown`), never silently converted to zero, false, empty, or success. Semantic services can answer only questions over options supplied by the caller. They cannot mutate catalogs, install or load skills, grant tools, choose paths, create IDs, or commit thews.

A canonical serialization of normalized task, catalogs, policy, and evidence produces snapshot references. Every request/response includes the versions and hashes needed for replay. Providers return typed answers; selection code owns their meaning.

## Runtime schema outlines

The following are the required Zod shapes; names are normative and fields not listed are not implicitly accepted.

`Task`: `{ taskId: StableId, taskAttemptId: TaskAttemptId, kind: string, objective: string, acceptance: string[], inputs: InputRef[], requiredCapabilities: Capability[], requiredArtifacts: ArtifactContract[], risk: RiskClass, budget: Budget, contextPolicy: ContextPolicy, mandatoryPersonaIds: StableId[], catalogSnapshotId: SnapshotId }`. IDs are caller/task-owned and never provider-created. Inputs and artifact references are scoped handles, not arbitrary paths.

`PersonaDefinition`: `{ id, version, role, positiveExamples: string[], negativeExamples: string[], requiredCapabilities, outputContract, requiredSkillIds, defaultSkillIds, eligibleSkillIds, modelOverride?: StableId, skillsOverride?: 'auto' | StableId[], workspacePolicy, artifactOwnership, reviewIndependence }`. `skillsOverride` absent and `'auto'` have dynamic semantics; an array is exact final pins. Required skills must be included by any explicit array. A persona may be mandatory by task policy, not by semantic confidence.

`Endpoint`: `{ id, version, provider, requestedModel, exactModel?: string, transport, availability, modalities, features, tools, contextLimit, dataHandling, authorizationScope, cost: {input: number | 'unknown', output: number | 'unknown'}, operationalEvidenceIds: StableId[] }`. Aliases and returned model metadata remain distinct. Availability and authorization are hard filters.

`SkillDefinition`: `{ id, version, contentHash, trust: 'reviewed'|'unreviewed'|'blocked', description, positiveExamples, negativeExamples, requiredCapabilities, requiredTools, prerequisites, sideEffectClass, conflicts, instructionTokenEstimate, artifactFormats }`. Skill text is not a grant; paths and body contents are never semantic output.

`ThewEvidence`: `{ id, subject: { endpointId?, personaId?, skillId?, taskFamily? }, metric, rubricVersion, value: number | Distribution | 'unknown', sampleCount: number | 'unknown', uncertainty: Interval | 'unknown', provenance: ProvenanceRef, measuredAt, validUntil?, applicability, status }`. Values must not be generalized outside their subject/applicability; unknown is preserved.

`DecisionRequest`: `{ decisionId, runId, stage: 'persona'|'model'|'skill', round: 1|2, inputClasses: ('settled_prompt'|'persona_definitions'|'model_catalog_metadata'|'skill_catalog_metadata')[], logicalCallId, state: RedactedState, questions: Record<QuestionId, Question>, catalogSnapshotId, policyVersion, deadlineMs, retryBudget, requestedModel, providerMode: 'recorded'|'deterministic'|'structured'|'typesafe-live' }`. Round 1 may contain only the initial user prompt or the orchestrator-settled/aggregated prompt after clarification or a grill session. Round 2 may contain selected persona definitions and only the model/skill catalog metadata needed for those decisions. Credentials, auth tokens, unrelated history, raw private memory, arbitrary filesystem content, and unneeded skill bodies are forbidden. Questions are closed and self-describing: `{ kind: 'choice'|'noul'|'score', instructions: string, criteria?: string, options?: Record<StableId, string>, levels?: string[] }`. Model/skill questions include the selected persona ID and, for 2b, the already-frozen model ID in state/instructions.

`DecisionResponse`: `{ decisionId, logicalCallId, provider, requestedModel, returnedModel?: string, answers: Record<QuestionId, Answer>, usage?: { inputTokens?: number, outputTokens?: number }, requestId?: string, providerTimingMs?: number, providerBilling?: number|'unknown', elapsedMs, attempts, provenance: 'synthetic'|'documented_example'|'recorded_live', providerContractHash, sdkVersion, responseHash }`. `Answer` is a discriminated union: Choice has `{ kind, winner, distribution: Record<optionId, finite number>, confidence?: finite number }`; Noul has `{ kind, value: finite number }`; Score has `{ kind, level, distribution, expected: finite number, confidence?: finite number }`. Runtime validation requires all requested answers exactly once, known IDs, finite probabilities, normalized sums within configured tolerance, and winner consistency. Missing timing/billing/usage is unknown, never inferred from the final response.

`ResolvedAssignment`: `{ memberId, rosterId, runId, taskAttemptId, ordinal, personaId, modelId, skillIds: StableId[], capabilityGrants: Capability[], artifactOwnership, policyVersion, catalogSnapshotId, decisionRefs, overrideRefs, policyAdjustments, status: 'frozen', frozenAt }`. It is constructed only by deterministic reconciliation and persisted as an ordered member of one immutable roster. No semantic answer is copied into a permission/grant field without an independent policy lookup.

`TypedError`: `{ code, phase, retryable, publicMessage, details: safe structured data, causeCode?, logicalCallId?, replanEligible }`. Codes include `INVALID_INPUT`, `CATALOG_INVALID`, `UNKNOWN_ID`, `UNAUTHORIZED`, `UNAVAILABLE`, `INCOMPATIBLE`, `CONTEXT_LIMIT`, `BUDGET_EXCEEDED`, `INVALID_DECISION`, `NO_MATCH`, `INSUFFICIENT_ELIGIBLE_PERSONAS`, `CONFIG_ERROR`, `PROVIDER_AUTH`, `PROVIDER_INVALID_REQUEST`, `PROVIDER_RATE_LIMITED`, `PROVIDER_OVERLOADED`, `PROVIDER_TIMEOUT`, `PROVIDER_MALFORMED_RESPONSE`, `REPLAN_EXHAUSTED`, `NON_REPLAYABLE`. Public messages never include secrets, raw prompts, headers, or full private content.

`TelemetryEvent`: `{ eventId, runId, taskAttemptId, occurredAt, type, parentId?, snapshotRefs, redactedPayload }`. Required types are `run.started`, `eligibility.completed`, `decision.requested`, `call.attempted`, `decision.received`, `override.bypassed`, `roster.policy_applied`, `assignment.reconciled`, `assignment.frozen`, `fallback.applied`, `replan.started`, `run.abstained`, `run.failed`, and `outcome.linked`. `override.bypassed` uses a closed payload `{ field: 'model'|'skills', source: 'persona'|'task'|'operator', requestedIdOrHash, validationResult, suppressedQuestions, policyVersion }`. Other payloads contain candidate IDs, raw validated distributions, exclusion codes, policy adjustments, latency, usage, attempts, and references—not private bodies.

## Deterministic semantics

1. Normalize and validate snapshots; reject duplicate IDs, invalid references, unreviewed/blocked privileged skills, and stale/hash-mismatched catalog records.
2. Filter availability, authorization, capabilities, context, workspace, review independence, and task budget before offering candidates.
3. Stage 1 receives only eligible persona metadata and a `none` option. Enforce the project `max_agents` policy from architecture; do not renormalize malformed distributions.
4. Stage 2 is ordered: 2a resolves dynamic models for selected personas, then code validates and freezes each model; 2b resolves dynamic skills using the frozen model. A pinned model skips 2a and constrains 2b; pinned skills skip 2b and constrain 2a; both skip inference.
5. Explicit skills arrays are exact. They suppress skill inference, may omit defaults, and must include required skills. `[]` with required skills is `CONFIG_ERROR`; invalid pins never silently substitute.
6. Reconcile each selected item against its own winner/fit and then jointly against budget, conflicts, capabilities, ownership, token/context, and reviewer rules. A different candidate's fit cannot validate the winner.
7. Freeze assignments transactionally and emit all bypasses, exclusions, adjustments, and unresolved unknowns.

## State-machine contract table

| State | Allowed transition | Required condition |
| --- | --- | --- |
| received | validated | task/schema/snapshot pass |
| validated | eligible | immutable normalized snapshot exists |
| eligible | persona-requested or abstained | eligible persona set and policy are available |
| persona-requested | persona-validated or failed | exact response correlation and runtime validation |
| persona-validated | roster-frozen or abstained | project `max_agents`, none, mandatory, tie rules pass |
| roster-frozen | model-requested or skill-requested or reconciled | selected personas only; overrides applied |
| model-validated | skill-requested or reconciled | each model is known and hard-valid |
| skill-validated | reconciled | each skill is known and model-conditioned |
| reconciled | assignment-frozen or replan-eligible | joint policy pass or one typed failure |
| frozen | terminal or replan-started | no mutation within attempt |

`fallback.applied` is a policy transition from abstained/typed provider failure to a newly validated configured assignment, never a bypass. Replan creates a new decision lineage and cannot exceed one use.

## Provider and replay contracts

`DecisionService.evaluate(request, signal): Promise<DecisionResponse>` must guarantee one response or one typed error for one logical call, with no hidden retries outside the shared deadline. The internal provider transport boundary is the sole owner of physical provider attempts and backoff; SDK retries are disabled. Every attempt and backoff consumes the same immutable logical-call deadline and retry budget; abort/cancel wins immediately, then deadline, then retry policy. No layer may retry outside that budget. Recorded and deterministic implementations must enforce the same response schema as TypeSafe. The conventional structured-output baseline is fixture-backed initially and must not be treated as a stronger authority than deterministic validation.

The TypeSafe implementation maps only the allowlisted wire fields and validates the parsed response with Zod. It uses the current documented System One shape (`model`, `state`, `questions`) and matching answer map, but does not copy SDK casts into domain trust. SDK retry defaults are disabled or instrumented under one outer deadline. `withResponse` metadata is allowlisted; request IDs are optional. Adapter tests cover 401, 422, 429, 529, timeout, abort, non-JSON success, malformed answers, missing answers, unknown IDs, invalid distributions, and alias/version mismatch.

Replay binds to exact canonicalization schema/version plus task-state, catalog, policy, question-set, response, provider-contract/SDK, and fixture-provenance hashes. Provenance is the closed union `synthetic | documented_example | recorded_live`. It performs validation and deterministic transitions only, makes no provider call or credential load, and is read-only against production run/decision/outcome tables; an explicitly requested audit may write only a separately scoped audit artifact. Deleted, redacted, or mismatched context returns `NON_REPLAYABLE`.

## Idempotency and resource limits

`taskAttemptId + stage + logicalCallId` is the logical idempotency key. SQLite unique constraints make repeated persistence safe. Physical retries use distinct `providerCallAttemptId` values and ordinals; future execution uses distinct `workerAttemptId`. Limits are independent: project `max_agents` 1..4 (initially 3), `max_dynamic_skills_per_agent` 1, separately configured model/fallback candidate and chain limits, question/context sizes, retry/attempt budgets, one explicit replan/generation, finite provider attempts, and a shared wall-clock deadline. Exceeding any limit is typed failure, not silent truncation; no generic K is a universal limit.

The yfere-owned `TaskAgentProvider` contract is the sole task-agent boundary. Its closed initial registry is exactly `codex | claude-code | opencode-go`; implementations are statically registered, with no dynamic plugin loading or marketplace. It covers auth preflight/status, start/resume/cancel, correlated events, tool/capability grants, workspace scope, requested/serving model identity, usage/cost with explicit unknowns, terminal/uncertain outcomes, artifacts/receipts, retry ownership, and provider/runtime version identity. Provider-specific semantics remain explicit: Codex uses yfere-owned browser OAuth and direct Responses; Claude uses an unmodified pinned native Claude Code runtime and native auth; OpenCode Go uses an independent API key and protocol-specific direct endpoints. `max_agents: 3` limits selected agents, not provider slots. TypeSafe/Jev remains decision-only; OpenAI Decisions remains deferred. No task-provider credential enters prompts, catalogs, decisions, SQLite, telemetry, fixtures, receipts, or artifacts.

### Normative TaskAgentProvider v1 contract

This is the sole normative task-agent contract; the provider research report is explanatory evidence only. The checked contract identity is `task-agent-provider/v1` and its source revision is the planning-package revision containing this section. Unknown fields are rejected at every boundary unless explicitly marked opaque; credentials and raw provider configuration are never serialized.

#### Closed schema notation (normative)

The following JSON-like definitions are closed objects: fields marked `?` are optional, `Opaque<T>` is an uninspectable non-secret handle, and every object rejects unknown fields. `Id`, `Hash`, `Timestamp`, `DurationMs`, and `Count` are non-empty UTF-8 strings, lowercase hexadecimal strings of the specified digest algorithm, RFC 3339 UTC timestamps, integers `>= 0`, and integers `>= 0` respectively. `Provider` is `codex | claude-code | opencode-go`; `Mode` is `offline | controlled_local | live`; `Signal` is an in-process cancellation signal and is not serialized.

`WorkspaceGrant = { root: Opaque<path>, allow: string[1..128], deny: string[0..128], readOnly: boolean }`; `CapabilityGrant = { tools: string[0..128], network: string[0..64], effects: string[0..64], approvalPolicy: Opaque<policy> }`; `ResourceLimits = { deadlineMs: DurationMs, maxOutputBytes: Count, maxEvents: Count, maxToolCalls: Count, maxRetries: Count, maxChildProcesses: Count }`; `EndpointSnapshot = { provider: Provider, origin: string, protocol: string, capturedAt: Timestamp, digest: Hash }`; `ExecutionProfile = { provider: Provider, mode: Mode, runtimePin: string, modelPin: string, dataPolicy: string, endpoint: EndpointSnapshot, profileDigest: Hash }`.

Provider authorization is a closed discriminated union: `CodexAuthorization = { provider: 'codex', connectionRef: Opaque<connection>, authSource: codex_oauth_registration | codex_oauth_account | codex_oauth_scope, authorizationHandle: Opaque<codex_authorization>, liveGate: Opaque<codex_live_gate> }`; `ClaudeAuthorization = { provider: 'claude-code', connectionRef: Opaque<connection>, authSource: claude_native_auth_ownership | claude_native_runtime_context, authorizationHandle: Opaque<claude_authorization>, liveGate: Opaque<claude_live_gate> }`; `OpenCodeGoAuthorization = { provider: 'opencode-go', connectionRef: Opaque<connection>, authSource: opencode_go_independent_key, authorizationHandle: Opaque<opencode_go_authorization>, liveGate: Opaque<opencode_go_live_gate> }`; `ProviderAuthorization` is exactly their union. Secret bytes, bearer tokens, native auth state, and credentialed URLs are never contract values; only the selected adapter resolves opaque handles.

`PolicyPins = { runtimePin: string, modelPin: string, dataPolicy: string, toolPolicyVersion: string, catalogHash: Hash, policyHash: Hash }`; `PreflightEvidence = { evidenceId: Id, provider: Provider, requestDigest: Hash, profileDigest: Hash, authorization: ProviderAuthorization, endpointDigest: Hash, protocolDigest: Hash, policyPins: PolicyPins, mode: Mode, liveGateIdentity: string, liveGateVersion: string, issuedAt: Timestamp, expiresAt: Timestamp, evidenceHash: Hash, revocationEpoch: Count }`. `evidenceHash` is SHA-256 over canonical UTF-8 serialization of every preceding field in schema order. Canonicalization rejects duplicate keys, unknown keys, alternate encodings, or omitted required fields; evidence is immutable and valid only when all provider, broker, gate, and revocation bindings verify.

`PreflightRequest = { runId: Id, taskAttemptId: Id, providerAuthorization: ProviderAuthorization, endpointSnapshot: EndpointSnapshot, executionProfile: ExecutionProfile, mode: Mode, requestDigest: Hash, profileDigest: Hash }`; `EventsRequest = { workerHandle: WorkerHandle, afterSequence: Count, maxEvents: Count }`; `CancelRequest = { workerHandle: WorkerHandle, reason: cancel_reason, cleanupDeadline: Timestamp }`, where `cancel_reason = operator | deadline | parent_cancel | resource_limit | policy_denied`. The serialized operation input is exactly one of these closed objects; `signal` is an in-process argument and is never serialized.

`CurrentRequestBinding = { requestDigest: Hash, profileDigest: Hash, provider: Provider, providerAuthorization: ProviderAuthorization, connectionRef: Opaque<connection>, endpointSnapshot: EndpointSnapshot, executionProfile: ExecutionProfile, workspace: WorkspaceGrant, capabilities: CapabilityGrant, limits: ResourceLimits, catalogHash: Hash, policyHash: Hash, toolPolicyVersion: string, outerDeadline: Timestamp, liveGateIdentity: string, liveGateVersion: string, preflightEvidenceHash: Hash, expiresAt: Timestamp, revocationEpoch: Count }`. `WorkerRequest = { runId: Id, taskId: Id, taskAttemptId: Id, workerAttemptId: Id, memberId: Id, assignmentHash: Hash, inputHandles: Opaque<input>[1..128], current: CurrentRequestBinding, preflightEvidence: PreflightEvidence }`. Before start, yfere recomputes both digests from the canonical current request/profile and requires equality across provider, discriminated authorization, connection, endpoint origin/protocol, runtime/model, data policy, mode, catalog/policy/tool identities, workspace/capability/resource grants, deadline, live gate, evidence hash/expiry, and revocation epoch; any missing, changed, stale, cross-provider, or mismatched field is rejected.

`AuthorizationBundle = { provider: 'codex', providerAuthorization: CodexAuthorization, preflightEvidence: PreflightEvidence, requestDigest: Hash, profileDigest: Hash, connectionRef: Opaque<connection>, sessionRef: Opaque<session>, memberId: Id, runtimeIdentity: string, workspace: WorkspaceGrant, capabilities: CapabilityGrant, limits: ResourceLimits, catalogHash: Hash, policyHash: Hash, liveGateIdentity: string, liveGateVersion: string, expiresAt: Timestamp, revocationEpoch: Count } | { provider: 'claude-code', providerAuthorization: ClaudeAuthorization, preflightEvidence: PreflightEvidence, requestDigest: Hash, profileDigest: Hash, connectionRef: Opaque<connection>, sessionRef: Opaque<session>, memberId: Id, runtimeIdentity: string, workspace: WorkspaceGrant, capabilities: CapabilityGrant, limits: ResourceLimits, catalogHash: Hash, policyHash: Hash, liveGateIdentity: string, liveGateVersion: string, expiresAt: Timestamp, revocationEpoch: Count } | { provider: 'opencode-go', providerAuthorization: OpenCodeGoAuthorization, preflightEvidence: PreflightEvidence, requestDigest: Hash, profileDigest: Hash, connectionRef: Opaque<connection>, sessionRef: Opaque<session>, memberId: Id, runtimeIdentity: string, workspace: WorkspaceGrant, capabilities: CapabilityGrant, limits: ResourceLimits, catalogHash: Hash, policyHash: Hash, liveGateIdentity: string, liveGateVersion: string, expiresAt: Timestamp, revocationEpoch: Count }`. Only secret/session handles are opaque; authority fields are closed and provider-discriminated. `ResumeRequest = { runId: Id, taskAttemptId: Id, workerAttemptId: Id, historyHandles: Opaque<history>[0..128], authorizationBundle: AuthorizationBundle, requestDigest: Hash, profileDigest: Hash, currentWorkspace: WorkspaceGrant, currentCapabilities: CapabilityGrant, currentLimits: ResourceLimits, outerDeadline: Timestamp, catalogHash: Hash, policyHash: Hash, liveGateIdentity: string, liveGateVersion: string, revocationEpoch: Count }`. Resume resolution revalidates every closed bundle field against the current request/profile and immutable preflight evidence, including member/provider/runtime/session/connection, all grants, hashes, deadline, gate, expiry, and revocation; it restores no ambient authority and replays no mutation.

Operation results are closed: `PreflightResult = { report: PreflightReport }`; `StartResult = { handle: WorkerHandle }`; `ResumeResult = { handle: WorkerHandle }`; `EventsResult = { events: Event[0..10000], nextSequence: Count, terminal: boolean, receipt?: TaskReceipt }`; `CancelResult = { receipt: CancellationReceipt }`. The invariant is `terminal=true iff receipt is present and valid`; a terminal event/result without a validated receipt is rejected. Every operation may instead return `ProviderError = { code: auth | unavailable | rate_limited | invalid_request | protocol | timeout | cancelled | resource_limit | policy_denied | workspace_denied | runtime_mismatch | version_mismatch | stale_evidence | revoked_evidence | uncertain_effect | internal, retryable: boolean, safeEvidence: string[0..2048], provider: Provider, operation: preflight | start | resume | events | cancel }`; `safeEvidence` excludes credentials, raw provider output, environment, and native session data.

`PreflightReport = { reportId: Id, requestDigest: Hash, profileDigest: Hash, evidence: PreflightEvidence, runtimeAvailable: boolean, runtimeVersion: string, credentialState: missing | configured_unverified | authenticated | expired | revoked | reauth_required | blocked | unknown, authMethod: native | app_oauth | api_key | none | unknown, remoteValidation: passed | failed | not_checked | unknown, modelCapability: passed | failed | not_checked | unknown, dataPolicy: passed | failed | not_checked | unknown, workspaceContainment: passed | failed | not_checked | unknown, egressPolicy: passed | failed | not_checked | unknown, processContainment: passed | failed | not_checked | unknown, resumeSupport: supported | unsupported | unknown, checkedAt: Timestamp, reportHash: Hash }`; reportHash covers canonical report fields and the exact evidence hash. Start/resume require the same request/profile digests and evidence hash; stale, expired, revoked, cross-provider, origin, protocol, runtime, model, policy, mode, or gate mismatches fail closed. `WorkerHandle = { handleId: Opaque<handle>, provider: Provider, runId: Id, taskAttemptId: Id, workerAttemptId: Id, memberId: Id, providerSessionRef?: Opaque<session>, runtimeIdentity: string, contractVersion: 'task-agent-provider/v1' }`.

`EventBase = { type: string, runId: Id, taskAttemptId: Id, workerAttemptId: Id, provider: Provider, sequence: Count, occurredAt: Timestamp }`. `Event` is a closed discriminated union: `{ type: 'worker.started', ...EventBase, payload: { runtimeIdentity: string } } | { type: 'text.delta', ...EventBase, payload: { text: string, redacted: boolean } } | { type: 'tool.proposed', ...EventBase, payload: { tool: string, argumentsDigest: Hash, approval: required | not_required } } | { type: 'tool.started', ...EventBase, payload: { tool: string, invocationId: Id } } | { type: 'tool.completed', ...EventBase, payload: { invocationId: Id, status: completed | failed | uncertain, outputDigest?: Hash } } | { type: 'permission.denied', ...EventBase, payload: { effect: string, reason: string } } | { type: 'usage.observed', ...EventBase, payload: { quantity: number | 'unknown', unit: string, scope: string, completeness: complete | partial | unknown } } | { type: 'retry.observed', ...EventBase, payload: { ordinal: Count, reason: string } } | { type: 'model.observed', ...EventBase, payload: { requested: string, serving: string, identityStatus: matched | changed | unknown } } | { type: 'worker.terminal', ...EventBase, payload: { status: completed | failed | cancelled | timed_out | crashed | uncertain, acceptance: passed | failed | not_checked, receipt: TaskReceipt } }`. Sequence starts at 0 and increases by one; duplicate, gap, cross-attempt, unknown, or non-redacted payloads fail closed.

`CancellationReceipt = { workerAttemptId: Id, requestedAt: Timestamp, status: cancelled | already_terminal | deadline | rejected | unknown, cleanup: complete | failed | uncertain, observedEffect: not_attempted | attempted_unconfirmed | confirmed_by_observation | unknown, providerEvidence?: string[0..2048], occurredAt?: Timestamp }`; `ObservedEffect = { effectId: Id, kind: created | modified | deleted | external | none, targetDigest: Hash, status: confirmed | unconfirmed | not_attempted | unknown }`; `Artifact = { handle: Opaque<artifact>, manifestHash: Hash, contentHash: Hash, sizeBytes: Count, retentionRef: Opaque<retention> }`; `TaskReceipt = { receiptId: Id, runId: Id, taskAttemptId: Id, workerAttemptId: Id, provider: Provider, status: completed | failed | cancelled | timed_out | crashed | uncertain, acceptance: passed | failed | not_checked, cleanup: complete | failed | uncertain, effects: ObservedEffect[0..128], artifacts: Artifact[0..128], verification: passed | failed | not_checked, verificationEvidence: string[0..2048], usage: { quantity: number | 'unknown', unit: string, scope: string, source: string, completeness: complete | partial | unknown, resetIdentity: string | 'unknown', costBasis: number | 'unknown' }, correlation: { runId: Id, taskAttemptId: Id, workerAttemptId: Id, eventStartSequence: Count, eventEndSequence: Count }, retentionRef: Opaque<retention>, runtimeIdentity: string, contractVersion: 'task-agent-provider/v1', receiptHash: Hash }`. `receiptHash` covers canonical receipt fields except itself. Effects/artifacts require valid enums, hashes, sizes, correlation, and no duplicate IDs; wrong hash/lineage or malformed entries fail closed. Receipts reject provider narratives, native sessions, auth files, raw environment, provider logs, and secrets.

Operation dispatch is exact: `preflight(PreflightRequest, Signal) -> PreflightResult | ProviderError`; `start(WorkerRequest, Signal) -> StartResult | ProviderError`; `resume(ResumeRequest, Signal) -> ResumeResult | ProviderError`; `events(EventsRequest, Signal) -> EventsResult | ProviderError`; `cancel(CancelRequest, Signal) -> CancelResult | ProviderError`. The initial registry is exactly `codex | claude-code | opencode-go`, statically registered; `max_agents` is project cardinality and never provider allocation. A connection reference is an unguessable non-secret handle resolved only inside the selected adapter's secret boundary and never serialized as a token, credentialed URL, prompt field, log, fixture, receipt, artifact, catalog value, or persistence payload. Cross-attempt handles are rejected.

Provider-required/forbidden fields are closed by `ExecutionProfile.provider`: Codex requires `authMethod=app_oauth`, direct Responses `protocol`, and a yfere OAuth authorization marker; it forbids API-key and native-session fields. Claude Code requires `authMethod=native`, `protocol=native-subprocess`, pinned runtime, and native auth ownership; it forbids token extraction/copy/replay, OAuth/API-key fields, and SDK executor fields. OpenCode Go requires `authMethod=api_key`, an approved direct protocol-family endpoint and independent key handle; it forbids CLI/server fallback, balance/credit fallback, and Codex/Claude auth fields. Any provider-mismatched or forbidden field fails closed. Tool grants, workspace containment, cancellation/reaping, redaction, and external-effect uncertainty remain yfere authority.

Jev, Decisions, browser, and secret-broker handles remain separate typed boundaries. No adapter is implementation-ready until all fixtures pass.

Authentication is transport-specific. The TypeSafe provider transport accepts only its separately configured API-key path and live authorization. The key remains in yfere's app-owned secret store until explicit removal/logout, replacement or rotation, provider revocation/expiry, or uninstall with credential removal; there is no arbitrary time-based deletion requirement, and it never enters config snapshots, telemetry, logs, prompts, SQLite decision records, or artifacts. A future Codex executor is a native yfere runtime initialized by `yfere auth codex`, with its own browser-OAuth flow, app-owned per-user refresh persistence, and direct Codex transport. Host execution, workspace/tool permissions, cancellation, and side-effect boundaries require a later native execution threat model. Neither credential may cross transports or appear in decision state, replay fixtures, or telemetry. Current public TypeSafe materials state that Jev is not trained on customer requests or responses, that zero data retention (ZDR) is offered to enterprise customers, and that the DPA retains Customer Personal Data for as long as necessary for the processing purpose and applicable law rather than for a fixed universal period. Those public statements do not establish this account’s plan, configured request/log retention, deletion route, applicable subprocessors/transfers, or ZDR entitlement; before live use, verify the actual account terms and decide whether ordinary account handling is acceptable or ZDR is required. A full workflow reports Jev-selection and Codex-executor preflight status independently.

## Phase 9/Gate C mode, grant, session, and receipt contracts

The following closed concepts are normative for native execution. A mode is selected policy data, never inferred from client behavior or a provider response. `WorkspaceMode = isolated_reviewed_apply | isolated_auto_apply`; all workspace changes begin in an isolated workspace. `isolated_reviewed_apply` requires an explicit reviewed apply-back; `isolated_auto_apply` is the dangerous, explicitly selected mode and may skip that apply approval. Auto apply-back changes only apply-back approval: it never widens filesystem, shell, git, network, credential, provider-live, browser, destructive-effect, or external-effect grants.

`ContinuationPolicy = CancelReapPolicy | BoundedContinuationPolicy`; `DisconnectMode = cancel_reap | bounded_continuation`. `CancelReapPolicy = { kind: 'cancel_reap' }`; `DetachObservation = { transitionId: Id, sessionId: Opaque<session>, runId: Id, taskAttemptId: Id, observedAt: Timestamp, clockIdentity: string }`; `BoundedContinuationPolicy = { kind: 'bounded_continuation', durationMs: DurationMs, detachedAt: Timestamp, expiresAt: Timestamp, resources: ResourceLimits, detachedOperations: string[1..128], stopAuthority: Opaque<stop_authority>, reconnect: require_same_session | explicit_rebind, terminalReceipt: deliver_on_reconnect | durable_delivery, expiry: reap_and_receipt | stop_and_receipt }`. At the trusted observed client-loss/detach transition, yfere creates exactly one `DetachObservation`; the canonical `detachedAt` is copied from that observation's `observedAt` only after exact session/run/task-attempt/transition correlation. It must not be precomputed, caller-selected, replayed from stale state, or supplied from a future event. Admission requires a trusted, monotonic clock state and `detachedAt` equal to the observed transition timestamp (not merely a nearby value). Duration arithmetic is overflow-safe: `durationMs` is a valid non-negative bounded integer, addition is checked before evaluation, and `expiresAt` must equal `detachedAt + durationMs` for the selected-duration policy; any overflow, mismatch, stale/future timestamp, untrusted clock, missing observation, or correlation failure is rejected. `detachedAt` and `expiresAt` are immutable canonical instants; `expiresAt` is the sole absolute deadline and the grant's `expiresAt` must be no later than it. Reconnect, rebind, resume, and process restart never reset, rewrite, renew, or extend `detachedAt`, `durationMs`, or `expiresAt`; failure to validate any clock/deadline/event invariant fails closed. The default is `cancel_reap`: client loss cancels work and reaps owned children, with cleanup and uncertainty reported in the terminal receipt. `bounded_continuation` is separately selected and its duration, resource ceilings, detached-operation allowlist, durable stop authority, reconnect rule, terminal receipt delivery, and expiry cleanup are all required policy data. It is never implied by `isolated_auto_apply`; detached operations cannot widen any grant.`

`ApprovalMode = single_operation | session_blanket`. Single-operation approval binds to the exact normalized operation and is consumed once. Session blanket approval is bounded to an explicit closed grant/capability envelope, applies only to the current client session, is revocable, expires when that session ends, and cannot cross credentials, projects, providers, or sessions. The UI and receipt must state whether destructive or external effects are included; ambient/global authority is invalid.

`ModeSelection = { workspace: WorkspaceMode, disconnect: DisconnectMode, continuation: ContinuationPolicy, approval: ApprovalMode, policyVersion: string, sessionId: Opaque<session> }`; the continuation discriminant must agree with `disconnect`, and unknown fields, omitted bounded fields, or mode widening are rejected. The canonical mode-selection digest covers every field, including the complete continuation policy.

`Grant = { grantId: Id, sessionId: Opaque<session>, projectId: Id, provider: Provider, workspace: WorkspaceGrant, capabilities: CapabilityGrant, destructiveEffects: boolean, externalEffects: boolean, credentialIdentity: Hash, authorizationIdentity: Hash, connectionIdentity: Hash, expiresAt: Timestamp, revocationEpoch: Count, continuationDigest: Hash, digest: Hash }`. The three identity hashes are non-secret stable identities, never credential bytes; they bind blanket authority to the credential/account, authorization source, and connection used to issue it. A grant is closed, digest-bound, session/project/provider scoped, and cannot authorize credentials or authority outside its fields. Any credential, authorization-source, connection, session, project, provider, or revocation-epoch change invalidates the grant before the next operation; reauthorization issues a new grant and digest. The grant digest covers all fields, including identity and continuation digests.

`ReceiptStatus = completed | failed | cancelled | timed_out | crashed | stopped | expired | reconnect_required | uncertain`; `ContinuationOutcome = not_detached | stopped | reconnected | expired | stop_uncertain | reconnect_uncertain`; `Receipt = { receiptId: Id, runId: Id, workerAttemptId: Id, modeSelectionDigest: Hash, grantDigest: Hash, status: ReceiptStatus, continuationOutcome: ContinuationOutcome, destructiveEffects: boolean, externalEffects: boolean, cleanup: complete | failed | uncertain, observedEffect: not_attempted | attempted_unconfirmed | confirmed_by_observation | unknown, telemetryRefs: Id[0..128], replayability: replayable | non_replayable | unknown, occurredAt: Timestamp, receiptHash: Hash }`. ### Approved host acceptance and retention policy (2026-10-03)

The full release-blocking native host/lifecycle suite runs on macOS arm64 and Linux x64. Linux arm64 and macOS x64 are required build/install/schema/replay/smoke hosts. Native execution fails closed without a matching accepted capability/host record; it never silently degrades isolation. Acceptance coverage must include filesystem case behavior; path and symlink containment; Git states and reviewed apply-back; process-tree cancellation/reaping and timeout escalation; crash/restart receipts; atomic artifact/receipt persistence; default-denied DNS/IPv4/IPv6/proxy boundaries; disk/resource limits; continuation deadline invariants; and explicit unsupported-host errors.

Retention defaults are global and configurable only through validated bounded configuration: structured run receipts 30 days; redacted structured telemetry 90 days; run/project artifacts 7 days after terminal state; accepted apply-back recovery artifacts 24 hours; rejected/abandoned apply-back artifacts 7 days; raw prompts/tool output/compaction sources disabled by default or 24 hours when explicitly enabled; raw object 10 MiB, total raw per run 50 MiB, artifact per run 100 MiB, project run-store 2 GiB; raw sweep hourly and artifact/receipt sweep daily. TTL begins at terminal time except raw capture TTL; inspect/reopen does not extend it; explicit retain is a new bounded decision, never infinite. Manual deletion is immediate logical deletion, removes indexes/caches/previews, leaves a minimal deletion receipt, and marks replay non-replayable without claiming SSD erasure. Active receipts, unresolved uncertain-effect evidence, and pending apply-back are protected from cap eviction. Cap pressure evicts expired then oldest eligible terminal artifacts, stops optional collection before required evidence, and records truncation/eviction.

Prospective fields are `retention.runReceiptTtl`, `retention.telemetryTtl`, `retention.artifactTtl`, `retention.acceptedApplyBackTtl`, `retention.rejectedApplyBackTtl`, `retention.rawCaptureEnabled`, `retention.rawTtl`, `limits.rawObjectBytes`, `limits.rawBytesPerRun`, `limits.artifactBytesPerRun`, `limits.runStoreBytes`, `sweeps.rawInterval`, and `sweeps.artifactReceiptInterval`. Every duration/interval is an integer count of milliseconds (`ms`); every size is an integer count of bytes (`B`). Values must be finite, non-negative-safe integers (no decimals, exponent-form strings, NaN, infinity, or numeric overflow) and satisfy these closed bounds: TTLs `3_600_000 <= value <= 31_536_000_000` ms (1 hour–365 days), sweep intervals `60_000 <= value <= 604_800_000` ms (1 minute–7 days), `rawObjectBytes` `1_024 <= value <= 1_073_741_824` B (1 KiB–1 GiB), `rawBytesPerRun` `1_024 <= value <= 4_294_967_296` B (1 KiB–4 GiB), `artifactBytesPerRun` `1_024 <= value <= 8_589_934_592` B (1 KiB–8 GiB), and `runStoreBytes` `1_048_576 <= value <= 1_099_511_627_776` B (1 MiB–1 TiB). Bounds are deliberately finite, safe-integer-compatible, include every approved default, and leave room for controlled fixtures without permitting unbounded retention or storage exhaustion. Cross-field validation requires `acceptedApplyBackTtl <= artifactTtl`, `rejectedApplyBackTtl <= artifactTtl`, `rawTtl <= runReceiptTtl`, `rawObjectBytes <= rawBytesPerRun <= artifactBytesPerRun <= runStoreBytes`, and each sweep interval <= the shortest applicable TTL; invalid or unknown fields fail closed. Defaults are a complete object; an override is a shallow, exact-key merge applied before validation, and omitted fields retain defaults. Overrides are global only, cannot vary by persona/provider/profile, cannot become infinite, cannot silently extend an active run (effective TTL is fixed at run start), and `rawCaptureEnabled` can become true only via an explicit raw-capture authorization—not as a side effect of any other override. Effective config, receipts, source attribution, policy version, and canonical digest include the post-merge values and override provenance.
